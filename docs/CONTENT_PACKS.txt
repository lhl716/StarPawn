StarPawn Content Packs, Rules, and Localization (Format Version 1)

Runtime entry point
  Game/ContentBootstrap.cs reads files inside this mod's directory during initialization through ModHelper.ModFileExists / ReadModFileText. It does not request arbitrary filesystem access.
  This entry point loads static content only. It does not read or write player saves or create bank, loan, securities, or pawn obligations.
  Missing files, unknown fields, unsupported versions, invalid coordinates, duplicate IDs, and missing textures/text keys log SP_CONFIG_BLOCKED and prevent business features from being enabled. Existing configuration and saves are not silently overwritten.

Files
  Content/settings.json: Language defaults to zh-CN; ExtensionFiles defaults to an empty list.
  Content/items.json: the base ContentPack. The original baseline contained 30 definitions; the current 0.3 catalog contains 239. SchemaVersion=1, PackId must be unique, and Items is the definition list.
  Content/Extensions/*.json: optional extension packs. Only filenames explicitly listed in settings.ExtensionFiles are read, in filename order. Names may contain letters, digits, underscores, hyphens, and the .json extension; paths are not allowed. Extensions append new definitions and cannot override existing IDs.
  Content/inspection-rules.json: level thresholds, XP per first discovery, hit tolerance, marker scale, maximum hotspots per definition, resale ratio, and certificate fee.
  Content/finance-rules.json: shared financial parameters, including interest rates, loan-to-value ratios, limits, gold/silver sell and buyback prices per gram, market ranges, and securities.
  Content/Localization/zh-CN.json: the base Chinese text table. Key is the stable text key, Source is the original phrase used to map legacy UI text, and Text is the displayed text.
  Content/Localization/en.json: a partial English override example. Keys without overrides retain Chinese text. This is not a complete English-language release.

Adding an item
  1. Copy docs/example-extension.json to Content/Extensions/engraved-bracelet.json.
     Set ExtensionFiles in Content/settings.json to ["engraved-bracelet.json"].
  2. Append Entries from docs/example-extension-localization.json to Entries in Content/Localization/zh-CN.json. The sample display strings are intentionally Chinese because this is the Chinese base locale.
  3. The example reuses the existing silver-bracelet texture and adds a separate commemorative-edition definition. It does not duplicate a physical AssetId. Catalog.CreateAsset still assigns a stable, unique ID to each new physical item.
  4. For new artwork, TextureKey must use the format starpawn: followed by lowercase letters, digits, or underscores. Supply both Textures/Paper/<filename>.png and Textures/Items/<filename>.png.
  5. Restart the mod to rebuild static registrations. Do not replace an existing ID's physical truth or anomaly IDs during a run; saved games contain references to these definitions and evidence entries.

Hotspots
  U/V is the center in the original image. Width/Height is the full width/height. All values are in 0..1, with 0,0 at the top left and 1,1 at the bottom right.
  Measure coordinates against the final texture. Draw actual damage inside the object, rather than floating color patches outside it.
  Use ViewId=front for the exterior and ViewId=window for the interior of an opened jade window. Interior evidence is invisible, unclickable, and ineligible for auto-discovery before the window is opened.
  Multiple hotspots may share the same CauseId for one EconomicCause. Valuation deduplicates by CauseId.
  Repairable identifies mechanical/surface causes that the workshop can fix. After at least one repairable issue is confirmed, one service repairs all repairable causes on the item. It does not award discovery XP for problems the player has not observed.
  RepairedTextureKey must show the actual repair result. A gold-plated item retains exposed base metal after its clasp is repaired; a console retains existing service marks after its port is repaired.

Purity and editions
  DeclaredPurityBasisPoints and ActualPurityBasisPoints are the claimed purity and physical truth, respectively; 10000=100%. Mass is stored in WeightMilligrams.
  DeclaredEditionId and EditionId are the claimed and actual editions, respectively. WorkId identifies the work; AssetId identifies each physical copy.
  The UI uses the Catalog.PublicFacts projection. It must not directly expose hidden true purity, edition, rough quality, or yield.
  Metal materials use the same financial market's sell and buyback prices per gram. Quotes separate MaterialValue and CraftPremium. A confirmed counterfeit must no longer receive a pure-gold or pure-silver floor.

Rule constraints
  LevelThresholds must start at 0 and increase strictly. The last entry is the mastery threshold; mastery automatically discovers predefined issues visible in the current view.
  ConsecutiveMissLimit must be 2. The user explicitly specified this gameplay rule, so configuration cannot bypass it.
  HitToleranceUv ranges from 0 to 0.02, default 0. MarkerScale ranges from 0.5 to 1.5, default 1. Changing hit tolerance does not change the texture boundaries of the physical defect.
  Static rules load at startup. Lowering thresholds can make an existing save reach mastery; evidence and XP history remain intact.

Localization
  Item NameKey/DescriptionKey/ReadingKey and hotspot LabelKey values are validated at load time and resolved into the current display language.
  Main interfaces use stable ui.* keys through TextResolver.LocalizeInline. The longest source phrase matches first, replacement is performed once, and dynamic numbers are not translated.
  Another language file needs only the matching Key and Text entries to override. Its Language must match settings. Unknown override keys are rejected.
  Conflicting translations for the same Source phrase are rejected so that identical UI phrases or item names cannot receive inconsistent wording.
  Category retains its stable business classification value. Display names use localization mappings. Changing language does not change market categories or cause financial side effects.

Validation and development
  tests/Run-ContentTests.ps1: pure business rules, save roundtrips, configuration, and localization invariants.
  tests/Run-ContentBootstrapTests.ps1: loading success/failure with real Newtonsoft.Json parsing and independent native API test doubles.
  Only pass export arguments when regenerating distribution defaults: Run-ContentTests.ps1 <absolute-path-to-content-contract.txt> export.
  Ordinary tests do not overwrite configuration. The game runtime does not export or overwrite these files.
